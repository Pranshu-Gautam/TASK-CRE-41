Method
------
The upsert executed for every POI is:

  INSERT INTO iris_staging.commercial_poi_staging (...) VALUES (...)
  ON CONFLICT (poi_uid) DO UPDATE SET ..., last_seen_at = now(), updated_at = now()
    WHERE commercial_poi_staging.row_hash <> excluded.row_hash
  RETURNING poi_uid, (xmax = 0) AS was_insert;

* conflict target is poi_uid, a stable hash of the operator's own record id,
  so re-running can never duplicate a row;
* the WHERE guard suppresses the write entirely when the content hash is
  unchanged, so an unchanged row returns nothing and is counted "unchanged";
* (xmax = 0) is true only for a genuine insert, so inserts and updates are
  MEASURED by PostgreSQL rather than inferred by the application;
* first_seen_at is excluded from the update set and therefore preserved.

or to the row_hash definition causes a one-time full re-write. That is the

should be expected after a pipeline upgrade and is not data drift.
